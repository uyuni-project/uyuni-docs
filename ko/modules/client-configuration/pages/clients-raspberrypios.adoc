= {raspberrypios} 클라이언트 등록
:description: 시스템을 준비하고, 소프트웨어 채널을 추가하고, 활성화 키를 사용하여 Raspberry Pi OS 클라이언트를 서버에 등록하십시오.
:revdate: 2026-08-24
:page-revdate: {revdate}

이 섹션에는 {raspberrypios} 운영 체제를 실행하는 클라이언트를 등록하는 방법에 대한 정보가 포함되어 있습니다.

부팅은 {raspberrypios} 클라이언트에서 초기 상태 실행을 수행하고 프로파일 업데이트를 위해 사용할 수 있습니다.

== 등록 준비


{productname} 서버에 {raspberrypios} 클라이언트를 등록하기 전에 약간의 준비가 필요합니다:

* DNS가 올바르게 구성되어 있고 클라이언트에 대한 항목을 제공하는지 확인하십시오.
  또는 {productname} 서버와 클라이언트 모두에서 적절한 항목으로 `/etc/hosts` 파일을 구성할 수 있습니다.
* 클라이언트는 등록 전에 {productname} 서버와 날짜 및 시간을 동기화해야 합니다.

== 활성화 키 생성

{raspberrypios} 채널에 연결된 활성화 키를 생성해야 합니다.

활성화 키에 대한 자세한 내용은 xref:client-configuration:activation-keys.adoc[]을 참조하십시오.




== GPG 키 관리

클라이언트는 소프트웨어 패키지가 설치되기 전에 GPG 키를 사용하여 패키지의 진위를 확인합니다.
신뢰할 수 있는 소프트웨어만 클라이언트에 설치할 수 있습니다.

[IMPORTANT]
====
GPG 키를 신뢰하는 것은 클라이언트의 보안을 위해 중요합니다.
어떤 키가 필요하고 신뢰할 수 있는지를 결정하는 것은 관리자의 임무입니다.
GPG 키가 신뢰되지 않을 때 소프트웨어 채널을 사용할 수 없기 때문에, 클라이언트에 채널을 할당하는 결정은 키를 신뢰하는 결정에 달려 있습니다.
====

GPG 키에 대한 자세한 내용은 xref:client-configuration:gpg-keys.adoc[]을 참조하십시오.

[NOTE]
====
{raspberrypios} 클라이언트에는 여러 개의 GPG 키가 설치되어야 할 수 있습니다.
====

서드파티 {raspberrypios} 리포지토리를 동기화할 때는 서버에서 적절한 GPG 키를 임포트해야 합니다.
GPG 키가 없으면 동기화가 실패합니다.

{raspberrypios} 리포지토리의 경우 메타데이터만 서명됩니다.
따라서 소프트웨어 채널에 대한 GPG 키를 임포트할 필요가 없습니다.
패키지는 {productname}에 의해 다시 서명되지 않습니다.

이미 {productname} 서버에 임포트된 GPG 키를 보려면 다음 명령을 실행하십시오:

----
mgrctl exec -- gpg --homedir /var/lib/spacewalk/gpgdir --list-keys
----

새 GPG 키를 임포트하려면 다음 명령을 실행합니다.

----
mgradm gpg add <filename>.gpg
----



== 루트 사용자 액세스

{raspberrypios}의 루트는 SSH 액세스에 대해 기본적으로 비활성화되어 있습니다.
일반 사용자 계정으로 온보딩하려면 클라이언트 시스템에서 `sudoers` 파일을 편집해야 합니다.

루트 사용자가 아닌 등록을 위해 `sudo`을(를) 구성하는 방법에 대한 자세한 지침은 xref:client-configuration:registration-sudo.adoc[]을(를) 참조하십시오.
