OpenSCAPによるシステムセキュリティ

Uyuni uses OpenSCAP to audit clients. SCAP content, tailoring files, and scan policies are managed centrally on the Uyuni server, and the server automatically deploys the required files to managed systems at scan time. This allows you to schedule and view compliance scans for any client, apply built-in or custom remediation, and set up recurring compliance monitoring.

1. SCAPについて

Security Content Automation Protocol (SCAP)は、コミュニティのアイデアから派生した相互運用可能な仕様を統合したものです。 これは、エンタープライズシステムのシステムセキュリティを維持するために、National Institute of Standards and Technology (NIST)によって維持されている一連の仕様です。

SCAPは、システムのセキュリティを維持するための標準化されたアプローチを提供するために作成されました。また、使用される標準は、コミュニティや企業のビジネスニーズを満たすために継続的に変更されます。 新しい仕様はNISTのSCAPリリースサイクルによって管理され、一貫性のある再現可能な改訂ワークフローを提供します。 詳細については、以下を参照してください。

  • https://csrc.nist.gov/projects/security-content-automation-protocol

  • https://www.open-scap.org/features/standards/

  • https://ncp.nist.gov/repository?scap

UyuniはOpenSCAPを使用してSCAP仕様を実装します。 OpenSCAPは、Extensible Configuration Checklist Description Format (XCCDF)を利用した監査ツールです。 XCCDFは、チェックリストの内容を表現する標準的な方法であり、セキュリティチェックリストを定義します。また、Common Platform Enumeration (CPE)、Common Configuration Enumeration (CCE)、Open Vulnerability and Assessment Language (OVAL)などの他の仕様と組み合わせて、SCAP検証済みの製品で処理できるSCAP表現のチェックリストを作成します。

OpenSCAP checks system security configuration settings and examines systems for signs of compromise, using rules based on standards and specifications. SUSE provides the SCAP Security Guide packages as a source of this content for SUSE systems; other operating system vendors provide equivalent content for their own distributions. For more information about the SUSE Security Team, see https://www.suse.com/support/security.

2. SCAPスキャンのためのクライアントの準備

開始する前に、SCAPスキャン用にクライアントシステムを準備する必要があります。

OpenSCAP監査は、SSH接続メソッドを使用するSaltクライアントでは使用できません。

Scanning clients can consume a lot of memory and compute power on the client being scanned. Ensure you have at least 2 GB of RAM available on each client to be scanned (especially for Red Hat-based and other modern clients).

Install the OpenSCAP scanner package on the client before you begin. Depending on the operating system, this package is included either on the base operating system, or in the Uyuni Client Tools.

You do not need to install the SCAP Security Guide (content) package on the client itself. Content files are uploaded to the Uyuni server and deployed automatically at scan time. Install the content package on any system (for example, your workstation, or temporarily on a client) to obtain the content files for upload, or obtain them directly from your operating system vendor. See SCAP content management.

3. SCAP content management

OpenSCAP uses SCAP content files to define test rules. These content files are created based on the XCCDF or OVAL standards. To get content files for upload to the Uyuni server, you can install the SCAP Security Guide package for your operating system (see SCAPスキャンのためのクライアントの準備) on any system to extract its default content files, obtain content files directly from your operating system vendor, download content from a reputable public source (such as the NIST National Checklist Program), or create your own custom content files if you are familiar with XCCDF or OVAL.

Custom or third-party SCAP content, including content downloaded from public repositories or created in-house, is not verified by SUSE and may fall outside your support agreement.

While running compliance scans with this content is read-only and safe for target systems, applying remediation derived from unverified sources can make unexpected system changes. Always test custom remediation in a non-production environment before applying it in production.

SCAP content files (DataStream and XCCDF) are uploaded and managed centrally on the Uyuni server. The server automatically deploys the required files to the managed system at scan time, so you do not need to manually transfer content files to clients.

3.1. Upload SCAP content

Procedure: Uploading SCAP content

  1. Navigate to Audit  OpenSCAP  SCAP Content.

  2. Click Upload.

  3. Provide a Name and optional Description.

  4. Upload the files:

    • DataStream file: The filename must end with -ds.xml.

    • XCCDF file: The filename must end with -xccdf.xml.

    • Both files must share the same base name (for example, ssg-sle15-ds.xml and ssg-sle15-xccdf.xml).

  5. Click Upload.

Uploaded files are stored on the server at /srv/susemanager/scap/ssg/content/.

3.2. Edit and delete SCAP content

Procedure: Editing and deleting SCAP content

  1. Go to Audit  OpenSCAP  SCAP Content.

  2. Click a content entry to edit its name, description, or replace the uploaded files.

  3. Click Delete to remove SCAP content.

Deleting SCAP content that is referenced by a policy will break that policy. Ensure no active policies depend on the content before deleting it.

3.3. OVAL files

Due to the large size of OVAL (Open Vulnerability and Assessment Language) files, they are not transferred automatically from the server to the managed system. If your SCAP evaluation requires OVAL files, you must ensure they are already present on the managed system before scheduling the scan.

You can specify OVAL file paths when creating a SCAP policy.

4. OpenSCAPプロファイルの検索

When you create a SCAP policy, or schedule a one-off scan by selecting SCAP content directly, in the Web UI, the list of available profiles is loaded automatically from the selected content file, so you do not usually need to look them up manually. Use the method in this section if you need to decide which content file to upload when a package provides several, or if you need the exact profile ID to pass to the system.scap.scheduleXccdfScanCustom API method, for example.

  4. Upload the tailoring file (XML format).

6. SCAP policies

SCAP policies define a reusable combination of SCAP content, a specific profile, and an optional tailoring file. Policies simplify the process of scheduling consistent compliance scans across your infrastructure, and are required for recurring scans.

Creating a policy is optional for a single, one-off scan. In that case you can select the SCAP content and profile directly when scheduling the scan, instead of creating a policy first. See Schedule SCAP scans.

6.1. Creating a policy

Procedure: Creating a policy

  1. Navigate to Audit  OpenSCAP  SCAP Policies.

  2. 作成をクリックします。

  3. Fill in the policy details:

    ポリシー名

    A unique name for the policy within your organization.

    説明

    An optional description of the policy’s purpose.

    SCAPコンテンツ

    Select from the uploaded SCAP content.

    XCCDFプロファイル

    Select a profile from the chosen SCAP content. The list of available profiles is loaded dynamically from the content file.

    テーラリングファイル

    (Optional) Select a tailoring file to customize the selected profile.

    テーラリングプロファイル

    (Optional) If a tailoring file is selected, choose a profile from the tailoring file.

    OVALファイル

    (Optional) Comma-separated list of OVAL file paths that must exist on the managed system.

    高度な引数

    (Optional) Additional oscap command-line arguments (for example, --skip-rule <rule_id>). For the options that are passed on, see Advanced arguments.

    リモートリソースのフェッチ

    (Optional) Enable to allow oscap to download remote XCCDF resources during evaluation.

  4. 作成をクリックします。

6.2. Advanced arguments

Uyuni does not pass the Advanced Arguments field to oscap as it is. It reads the options it supports from the field, and builds the oscap command line on the managed system from them. This applies to policies, to one-off scans, and to the advancedArgs key of the API.

These options are passed on:

Option Effect

--rule <rule_id>

Evaluate only the given rule. Can be given more than once.

--skip-rule <rule_id>

Do not evaluate the given rule. Can be given more than once.

--reference <name>:<id>

Evaluate only the rules that carry the given reference, for example stigid:RHEL-09-211010.

--cpe <file>

Use the given CPE dictionary or language for the applicability checks.

--local-files <directory>

Use the local copies of remote resources from the given directory instead of downloading them.

--datastream-id <id>

Use the given data stream of the collection.

--xccdf-id <id>

Use the given XCCDF component of the data stream.

--benchmark-id <id>

Evaluate the given benchmark, when the data stream holds more than one.

--tailoring-id <id>

Use the given tailoring component of the data stream.

--fetch-remote-resources

Download the remote content that the SCAP content refers to.

--remediate

Run the fixes of the failed rules after the evaluation.

The profile, the tailoring file, and the tailoring profile are selected with their own fields. Other options are ignored, and the scan sets the result and report options itself.

For example, to skip two rules of the selected profile:

--skip-rule xccdf_org.ssgproject.content_rule_package_telnet-server_removed --skip-rule xccdf_org.ssgproject.content_rule_package_tftp-server_removed

The paths given to --cpe and --local-files are read on the managed system. Only the SCAP content and the tailoring file are transferred from the server.

--skip-rule, --reference, --cpe, --local-files, --datastream-id, --xccdf-id, --benchmark-id, and a repeated --rule need an updated Salt bundle (venv-salt-minion) on the managed system. With an older Salt bundle, these options are ignored, and a repeated --rule makes the scan fail.

7.3. Recurring scans

SCAP policies can be scheduled as recurring actions, enabling automated compliance monitoring.

To set up a recurring scan, run the procedure:

Procedure: Setting up a recurring scan

  1. Navigate to the recurring actions configuration for a system or system group.

  2. Select SCAP Policy Scan as the action type.

  3. Choose the SCAP policy to apply.

  4. Configure the recurrence schedule (for example, daily, weekly).

Recurring scans are linked to the selected SCAP policy. If you update the policy (for example, change the profile), future recurring scans will use the updated configuration.

7.4. Scheduling a scan from the API

You can also use the Uyuni API to schedule SCAP scans, with the system.scap handler.

Procedure: Scheduling a scan from the API

  1. 開始する前に、スキャンするクライアントにPythonおよびXML-RPCライブラリがインストールされていることを確認します。

  2. To schedule a scan using an existing SCAP policy, use system.scap.scheduleXccdfScanWithPolicy:

    #!/usr/bin/python3
import xmlrpc.client
client = xmlrpc.client.ServerProxy('https://server.example.com/rpc/api')
key = client.auth.login('username', 'password')
client.system.scap.scheduleXccdfScanWithPolicy(key, [<1000010001>], <policy_id>, xmlrpc.client.DateTime())
client.auth.logout(key)

    この例では:

    • [<1000010001>] is the list of system IDs (sids) to scan.

    • <policy_id> is the ID of an existing SCAP policy.

  3. To schedule a scan without a saved policy, use system.scap.scheduleXccdfScanCustom and pass the SCAP content and profile directly:

    #!/usr/bin/python3
import xmlrpc.client
client = xmlrpc.client.ServerProxy('https://server.example.com/rpc/api')
key = client.auth.login('username', 'password')
params = {
    'scapContentId': <scap_content_id>,
    'xccdfProfileId': '<profile_name>',
}
client.system.scap.scheduleXccdfScanCustom(key, [<1000010001>], params, xmlrpc.client.DateTime())
client.auth.logout(key)

    この例では:

    • <scap_content_id> is the ID of previously uploaded SCAP content.

    • <profile_name> is the XCCDF profile ID to use (for example, xccdf_org.ssgproject.content_profile_stig). params can also include the optional keys tailoringFileId, tailoringProfileId, ovalFiles, advancedArgs, and fetchRemoteResources. For the options that advancedArgs passes on, see Advanced arguments.

  4. コマンドプロンプトから、スキャンするクライアント上でスクリプトを実行します。

8. How scans work

When a scan is scheduled:

  1. The Uyuni server transfers the required SCAP content files (DataStream and XCCDF) from the server to the managed system using Salt’s file management.

  2. If a tailoring file is associated with the policy, it is also transferred.

  3. The oscap tool is executed on the managed system with the appropriate parameters (profile, rules, tailoring, etc.).

  4. Scan results (results.xml and report.html) are collected from the managed system and stored on the server.

  5. Results are available for review in the WebUI under the system’s audit section.

Files are transferred to /var/cache/salt/minion/scap/ on the managed system.

OVAL files are not transferred automatically due to their large size. If your scan requires OVAL files, they must be present on the managed system before the scan runs.

11. 修復

You can remediate non-compliant systems either directly from SCAP scan results in the Web UI, or by running the Bash scripts and Ansible playbooks provided in the SCAP Security Guide packages.

Remediation actions change system configuration to enforce compliance, and can disable services, change permissions, or otherwise affect how a system behaves. This applies to built-in remediation, custom remediation scripts, and the Bash scripts and Ansible playbooks described below. Test remediation on non-production systems before applying it to production systems.

11.1. Remediation from scan results

After reviewing scan results, you can apply remediation for individual rules that have failed.

Procedure: Applying remediation from scan results

  1. Navigate to a completed scan’s results.

  2. Identify the non-compliant rule.

  3. Click the remediation action to apply the fix.

Built-in remediation derived from SCAP content is always a Bash script, pre-populated from the SCAP content’s built-in fix elements. When you apply it, Uyuni runs it on the managed system as a remote command, as root.

SCAP content does not provide Salt-based remediation. If you prefer to remediate with a Salt state instead, define a Custom remediation for the rule and write your own Salt state in the empty text area; unlike Bash, there is no built-in content to pre-populate it.

SCAP Security Guide packages also provide standalone Ansible playbooks for full-profile hardening. Uyuni only reads Bash-type fix elements for the per-rule remediation described here; Ansible playbooks are not applied from the Web UI and must be run manually. See Run remediation using a Bash script or Ansible playbook.

11.2. Custom remediation

If the built-in remediation from the SCAP content is insufficient or you need to tailor the fix for your environment, you can define custom remediation scripts.

Custom remediation is scoped per organization and per rule.

To save a custom remediation, follow these steps:

Procedure: Saving a custom remediation

  1. Navigate to the rule’s remediation view.

  2. Choose the script type:

    • Bash: A custom shell script.

    • Salt: A custom Salt state definition.

  3. Enter or modify the remediation script.

  4. 保存をクリックします。

Custom remediation overrides the default remediation from the SCAP content for the specific rule within your organization.

Custom remediation includes an audit trail. The system tracks which user created and last modified each custom remediation script.

11.3. Deleting custom remediation

You can delete a custom remediation to revert to the default remediation provided by the SCAP content.

Navigate to the custom remediation view and click Delete for the specific script type.

11.4. Run remediation using a Bash script or Ansible playbook

Remediation Bash scripts and Ansible playbooks are provided in the same SCAP Security Guide packages to harden the client systems, independently of the Web UI remediation workflow described above. Use this method if you want to apply a full hardening profile proactively, without first running a scan, or if you prefer not to apply remediation from the Web UI for some reason.

例:

Listing 1. bashスクリプト
/usr/share/scap-security-guide/bash/sle15-script-cis.sh
/usr/share/scap-security-guide/bash/sle15-script-standard.sh
/usr/share/scap-security-guide/bash/sle15-script-stig.sh
Listing 2. Ansible playbook
/usr/share/scap-security-guide/ansible/sle15-playbook-cis.yml
/usr/share/scap-security-guide/ansible/sle15-playbook-standard.yml
/usr/share/scap-security-guide/ansible/sle15-playbook-stig.yml

クライアントシステムでAnsibleを有効にした後、リモートコマンドまたはAnsibleを使用して実行できます。

11.4.1. リモートコマンドとして単一システムでBashスクリプトを実行する

単一システムでリモートコマンドとしてBashスクリプトを実行します。

  1. システム  概要タブから、インスタンスを選択します。 次に、詳細  リモートコマンドで、Bashスクリプトを次のように記述します。

    #!/bin/bash
chmod +x -R /usr/share/scap-security-guide/bash
/usr/share/scap-security-guide/bash/sle15-script-stig.sh

  2. Schedule をクリックします。

Folder and script names change between distribution and version. Install the content package for your operating system (see SCAPスキャンのためのクライアントの準備), then use rpm -ql <package> or dpkg -L <package> to list the exact script and playbook paths available.

11.4.2. 複数のシステムでシステムセットマネージャを使用してbashスクリプトを実行する

複数のシステムでリモートコマンドとして一度にBashスクリプトを実行します。

  1. When a system group has been created click System Groups, select Use in SSM from the table.

  2. From the System Set Manager, under Misc  Remote Command, write a Bash script such as:

    #!/bin/bash
chmod +x -R /usr/share/scap-security-guide/bash
/usr/share/scap-security-guide/bash/sle15-script-stig.sh

  3. Schedule をクリックします。

13. Workflow example

The following example demonstrates a typical end-to-end workflow:

  1. Upload SCAP content:

    Navigate to Audit  OpenSCAP  SCAP Content and upload a SCAP Security Guide DataStream file (for example, ssg-sle15-ds.xml and ssg-sle15-xccdf.xml).

  2. Upload a tailoring file (optional):

    Navigate to Audit  OpenSCAP  Tailoring Files and upload a tailoring file if you need to customize a profile.

  3. Create a SCAP policy:

    Navigate to Audit  OpenSCAP  SCAP Policies and create a policy that references the uploaded content, selects a profile (for example, CIS Benchmark Level 1), and optionally includes the tailoring file.

  4. Schedule a scan:

    Navigate to a system’s Audit  OpenSCAP  Schedule tab, select the policy, and schedule the scan.

  5. Review results:

    After the scan completes, review the results under the system’s Audit  OpenSCAP  List Scans tab.

  6. Apply remediation:

    For any non-compliant rules, apply the built-in remediation or define custom remediation scripts tailored to your environment.

  7. Set up recurring scans:

    Configure recurring scans using the SCAP policy to maintain ongoing compliance monitoring.
