==== イメージの検査

ベースコンテナイメージ（BCI）には実行に必要なすべてのソフトウェアが含まれていますが、軽量であるため、検査に必要なすべてのツールやライブラリが含まれていない場合があります。

コンテナイメージの検査を実行する際、{productname}はビルドホスト（検査がスケジュールされている場所）から{salt}バンドル（`venv-salt-minion`）をコピーしてターゲットコンテナに展開し、コンテナ内でそれを実行します。
そのため、ターゲットコンテナイメージは、ビルドホストの{salt}バンドルの動的依存関係をすべて満たしている必要があります。

ターゲットイメージに必要な動的ライブラリが不足している場合、検査は失敗します。
たとえば、次のようなエラーメッセージが表示されることがあります。

----
libssl.so.1.1: cannot open shared object file: No such file or directory
----

最も一般的な依存関係の問題はOpenSSLライブラリに関するものです。これは、{salt}バンドルのPythonモジュールがビルドホストのOpenSSLバージョンに対して動的にリンクされているためです。
OpenSSLのバージョンは主要なオペレーティングシステムのバージョン（SLE 15やSLE 16など）によって異なるため、互換性はビルドホストとターゲットイメージの両方に依存します。

* **SLE 15ビルドホストの場合**:
  {salt}バンドルはOpenSSL 1.1に対してコンパイルされています（`libssl.so.1.1`を提供）。
  したがって、SLE 15ビルドホストで検査されるイメージには、OpenSSL 1.1がインストールされている必要があります（通常は`libopenssl1_1`パッケージ経由で）。
  OpenSSL 1.1はSLE 16およびopenSUSE Leap 16では利用できないため、SLE 16 / Leap 16イメージをSLE 15ビルドホストで検査することは*できません*。

* **SLE 16ビルドホストの場合**:
  {salt}バンドルはOpenSSL 3に対してコンパイルされています（`libssl.so.3`を提供）。
  したがって、SLE 16ビルドホストで検査されるイメージには、OpenSSL 3がインストールされている必要があります（通常は`libopenssl3`パッケージ経由で）。

イメージの検査を確実に成功させるために、以下のベストプラクティスに従ってください。

* ビルドホストとターゲットイメージのメジャーオペレーティングシステムバージョンを一致させてください。たとえば、SLE 16 / Leap 16イメージの検査にはSLE 16 / Leap 16ビルドホストを使用し、SLE 15イメージの検査にはSLE 15ビルドホストを使用してください。
* イメージ内に正しいバージョンのOpenSSLをインストールし（たとえば、SLE 16の場合は`libopenssl3`、SLE 15の場合は`libopenssl1_1`を`Dockerfile`に追加）、イメージを再構築してください。

同様の依存関係の要件は、`libexpat`などの他の動的ライブラリにも適用されます。
