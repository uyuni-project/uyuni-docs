[IMPORTANT]
====
アップグレードの前に、{productname}で使用されるすべてのルートおよび中間CA証明書が、`X509v3 Basic Constraints`を`critical`としてマークし、`CA:TRUE`を含んでいることを確認してください。
Python 3.13以降を含む厳格な証明書バリデーターは、`critical`フラグが欠落しているCA証明書を拒否します。

インストール環境で{productname}によって生成された古い自己署名CAを使用している場合は、新しいCAと新しいサーバー証明書を作成し、新しいルートCAをすべてのクライアントにデプロイする必要があるかもしれません。

新しい `mgradm ssl` コマンドを使用して、Podman インストール上のCA証明書をローテーションできます。
詳細については、xref:administration:ssl-certs-ca-migration.adoc[] を参照してください。

このコマンドは、`mgradm`と{productname} の両方をアップグレードした*後*にのみ使用できることに注意してください。
CA証明書をローテーションし、サーバーを起動する前に クライアントがそれらを認識していることを確認する限り、影響を受けるインストールを安全にアップグレードできます。

CA証明書のローテーションを怠った場合、直ちにシステムエラーが発生するとは限りませんが、そのような対応は強く推奨されません。
====
