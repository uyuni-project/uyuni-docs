= 服务器从 5.1 升级到 5.2
:description: 按照迁移步骤操作，并验证新版本和组件，将服务器从 5.1 版本升级到 5.2 版本。
:revdate: 2026-09-15
:page-revdate: {revdate}


[IMPORTANT]
====
升级前必须停止 {productname} 5.1。
====

[IMPORTANT]
====
在升级到 {productname} {productnumber} 之前，您必须将 {productname} 5.1 服务器更新到最新的可用维护更新，并确保其正在运行（请参阅 xref:installation-and-upgrade:container-management/updating-server-containers.adoc[Server Maintenance Update]）。
数据库架构迁移需要来自先前维护更新的中间更改。
直接从较旧的维护更新进行升级可能会导致数据库迁移错误和服务器启动故障。
====

[IMPORTANT]
====
有关已知问题的列表，请参见 link:https://documentation.suse.com/releasenotes/multi-linux-manager/5.2/#known_issues[{productname} Release Notes]。
====

== {sl-micro} 6.1 到 {sl-micro} 6.2



本文件提供了经过测试的升级流程，用于将部署了 {sl-micro} 6.1 主机的 {productname} 5.1 服务器升级到 {sl-micro} 6.2 并迁移到 {productname} {productnumber}。


=== 先决条件

* {productname} 5.1 已安装并在 {sl-micro} 6.1 上运行。
* {productname} 5.1 已更新到最新的可用维护更新，并且正在运行（请参阅 xref:installation-and-upgrade:container-management/updating-server-containers.adoc[Server Maintenance Update]）。
* 系统已注册到 {scc} 且拥有有效的订阅。


=== 发行套件升级和服务器迁移

.过程：升级从 {productname} 5.1 迁移到 {productname} {productnumber}
[role=procedure]
_____

. 校验当前产品状态

+

[source,console]
----
SUSEConnect --status-text
----

+

确认以下信息：

* 基础操作系统：`SL Micro 6.1`
* 扩展：`SUSE Multi-Linux Manager Server 5.1 Extension`

+

. 确保主机系统已更新。

+

[NOTE]
====
此步骤将更新主机操作系统软件包和工具（例如 `mgradm`）。
在执行此过程之前，请确保 {productname} 服务器容器已更新到最新的维护更新并正在运行。
====

+

[source,console]
----
transactional-update patch
----

+

--

* 如果已应用补丁，请在继续迁移前\\**重引导系统**：

+

[source,console]
----
mgradm stop
reboot
----

* 如果未发现更新，可直接进入迁移步骤。

--

+

. 启动迁移流程：

+

[source,console]
----
transactional-update migration --auto-agree-with-licenses --gpg-auto-import-keys
----

+

按照提示操作，选择可用的迁移目标：**SUSE Linux Micro 6.2** 和 **{productname} 服务器扩展 {productnumber}**。

+

. 停止服务器后重引导，使更改生效。

+

[source,console]
----
mgradm stop
reboot
----

+

. 重引导后的检查：

+

验证 {productname} 扩展和 {productname} 版本：

+

[source,console]
----
SUSEConnect --status-text
mgradm --version
----

+

预期输出：

* 扩展：`SUSE Multi-Linux Manager Server {productnumber} Extension`
* 版本：`mgradm version 5.2.0` 或更高版本

=== 迁移完成

服务器主机系统现在运行的是 {sl-micro} 6.2，并带有更新的 {productname} {productnumber} 服务器软件包。

如果您有一个连接到此服务器的 {productname} 5.1 代理，请参阅 xref:installation-and-upgrade:container-deployment/mlm/migrations/proxy/proxy-mlm-51-52.adoc[Proxy Upgrade 5.1 > 5.2] 指南以升级代理主机。

== {sles} 15 SP7

本文件提供了升级流程，用于将部署了 {sles} 15 SP7 主机的 {productname} 5.1 服务器升级到 {productname} {productnumber}。


=== 先决条件

* {productname} 5.1 已安装并在 {sles} 15 SP7 上运行。
* {productname} 5.1 已更新到最新的可用维护更新，并且正在运行（请参阅 xref:installation-and-upgrade:container-management/updating-server-containers.adoc[Server Maintenance Update]）。
* 系统已注册到 {scc} 且拥有有效的订阅。


=== 升级和迁移

.过程：升级更新 {productname} 15 SP7 上的 {sles} 组件
[role=procedure]
_____

. 校验当前产品状态

+

[source,console]
----
SUSEConnect --status-text
----

+

确认以下信息：

* 基础操作系统：`SUSE Linux Enterprise Server 15 SP7`
* 扩展：`SUSE Multi-Linux Manager Server 5.1 Extension`

+

. 确保主机系统已更新。

+

[NOTE]
====
此步骤将更新主机操作系统软件包和工具（例如 `mgradm`）。
在执行此过程之前，请确保 {productname} 服务器容器已更新到最新的维护更新并正在运行。
====

+

[source,console]
----
zypper patch
----

+

如果已应用补丁，请在继续迁移前停止服务器，然后重引导系统：

+

[source,console]
----
mgradm stop
reboot
----

+

. 执行迁移到 {productname} {productnumber}。

+

[source,console]
----
zypper migration
----

+

选择您的时区。

* `{productname} Server Extension {productnumber}`

+

. 停止服务器后重引导，使更改生效。

+

[source,console]
----
mgradm stop
reboot
----

+

. 重引导后的检查：

+

验证 {productname} 扩展：

+

[source,console]
----
SUSEConnect --status-text
----

+

预期输出：

* 扩展：`SUSE Multi-Linux Manager Server {productnumber} Extension`

+

. 验证 {productname} 版本。

+

[source,console]
----
mgradm --version
----

+

预期输出：

* 版本：`mgradm version 5.2.0` 或更高版本

+

. 升级服务器容器

+

endif::[]

ifdef::backend-pdf[]

endif::[]

+

[source,console]
----
mgradm start
mgradm upgrade
----

+

按照提示操作，拉取并配置新的 5.2.x 容器。

* `server-postgresql:5.2.0` 或更高版本

=== 迁移完成

服务器主机系统现在运行 {sles} 15 SP7，并带有更新的 {productname} {productnumber} 服务器软件包。
