. Deploy {productname}.

+

[NOTE]
====
If you use VM images as a migration target, here as the last step, execute the command `mgradm migrate` instead of `mgradm install`.
====

+

Execute one of the following commands, depending on the SSL certificate variant (self-signed or third-party).
  Replace `<FQDN>` with your fully qualified domain name of the {productname} Server:

+

--
* Using self-signed certificates provided by {productname}:

+

[source,shell]
----
mgradm install <FQDN>
----

* With importing SSL certificates using third-party SSL certificate flags (the example can adjusted if not all these certificates are needed):

+

[source,shell]
----
mgradm install <FQDN> \
  --ssl-ca-intermediate <strings> \
  --ssl-ca-root <string> \
  --ssl-server-cert <string> \
  --ssl-server-key <string> \
  --ssl-db-ca-intermediate <strings> \
  --ssl-db-ca-root <string> \
  --ssl-db-cert <string> \
  --ssl-db-key <string>
----

[NOTE]
====
By default, the TFTP server container is not deployed on the server.
For autoinstallation (PXE/TFTP), using a {productname} Proxy is recommended.
If you need to run the TFTP service directly on the server without a proxy (discouraged), append the `--tftpd-enable` flag to `mgradm install`.
====

+

For more information, see `mgradm install --help`.
