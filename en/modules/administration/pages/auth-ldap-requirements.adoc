[[ldap-group-requirements]]
= LDAP Group Requirements
:revdate: 2026-08-31
:page-revdate: {revdate}

When configuring LDAP authentication in {productname}, the directory server must use specific group object classes and attributes depending on your server type.

== Required Group Structure

.OpenLDAP and FreeIPA
For *OpenLDAP* and *FreeIPA* server types, groups must use:

* Object class: `groupOfNames` or `groupOfUniqueNames`
* Member attribute: `member` with **full user DN values**

.Example OpenLDAP Group Entry
[source,ldif]
----
dn: cn=uyuni-admins,ou=Groups,dc=example,dc=com
objectClass: groupOfNames
cn: uyuni-admins
member: uid=alice,ou=People,dc=example,dc=com
member: uid=bob,ou=People,dc=example,dc=com
----

[IMPORTANT]
====
The `member` attribute must contain the **complete Distinguished Name (DN)** of each user, not just the username.

For example: `uid=alice,ou=People,dc=example,dc=com`, not `alice`.
====

.Active Directory
For *Active Directory* server types, groups use:

* Object class: `group`
* Member attribute: `member` with full user DN values

== Default Group Filters

Each server type has a default group filter that {productname} uses to find a user's groups:

[cols="1,2",options="header"]
|===
| Server Type | Default Group Filter

| OpenLDAP
| `(&(objectClass=groupOfNames)(member={userDn}))`

| FreeIPA
| `(&(objectClass=groupOfNames)(member={userDn}))`

| Active Directory
| `(&(objectClass=group)(member={userDn}))`
|===

The `{userDn}` placeholder is replaced with the user's full DN at search time.

== Using posixGroup (Custom Configuration)

If your directory uses POSIX groups (`posixGroup` with `memberUid` attribute), you must configure a **custom group filter**:

.Example Custom Filter for posixGroup
[source]
----
(&(objectClass=posixGroup)(memberUid={login}))
----

[NOTE]
====
The `{login}` placeholder is replaced with the username (not the full DN).

The group's `cn` attribute is used as the group name for role mapping.
====

.Example posixGroup Entry
[source,ldif]
----
dn: cn=uyuni-admins,ou=Groups,dc=example,dc=com
objectClass: posixGroup
cn: uyuni-admins
gidNumber: 10000
memberUid: alice
memberUid: bob
----

== Troubleshooting Group Resolution

If group resolution is not working:

. Use the *Test Group Resolution* function in menu:Admin[Setup Wizard > LDAP] to verify group membership for a test user.
. Check that your groups match the required object class for your server type.
. Verify that the member attribute uses **full DNs** (for `groupOfNames`) or **usernames** (for `posixGroup`).
. If using a custom directory schema, configure a custom group filter that matches your structure.
