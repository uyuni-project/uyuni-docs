The channel access tokens that Salt clients use to download packages from {productname} expire and are replaced regularly.
A Taskomatic job named [literal]``TokenCleanup`` refreshes the tokens in the server database, and then deploys the new credentials to the affected clients.

If a client is offline or unreachable when the job runs, the server database holds the new token but the client does not.
The job does not retry on later runs, because it finds the tokens in the database valid.

When this happens, the client keeps outdated tokens in [path]``/etc/zypp/repos.d/susemanager:channels.repo``.
Running [command]``zypper ref`` or [command]``zypper up`` directly on the client, or using an external tool that does so, does not refresh the tokens and fails with an error like this:

----
Retrieving repository '<repository name>' metadata ....[error]
Repository '<repository name>' is invalid.
[susemanager:<channel label>|https://<server>:443/rhn/manager/download/<channel label>?<token>] Valid metadata not found at specified URL
----

On the server, [path]``/var/log/rhn/rhn_web_ui.log`` records the rejected requests as [literal]``INFO`` messages like [literal]``Forbidden: Token ... is not valid to access repomd.xml``.
The same [literal]``Valid metadata not found`` message can also be caused by incomplete repository metadata regeneration.
For more information, see xref:administration:troubleshooting/tshoot-taskomatic.adoc[].

To fix this, schedule a recurring action for the organization that redeploys the certificates and channel configuration.
Clients that were unavailable during a token refresh then receive the current tokens the next time the action runs.



.Procedure: Keeping Channel Tokens Synchronized
. In the {productname} {webui}, navigate to menu:Admin[Organizations].
. Click the name of the organization to configure.
. Navigate to the [guimenu]``Recurring Actions`` tab and click btn:[Create].
. Select an action type from the [guimenu]``Action Type`` dropdown:
* [guimenu]``Highstate`` applies the complete configuration of each client.
* [guimenu]``Custom state`` applies only the states you select.
  Select [guimenu]``Sync All``, [guimenu]``Certificates``, and [guimenu]``Channels``, which are the [literal]``util.syncall``, [literal]``certs``, and [literal]``channels`` states, and drag and drop them into this order.
. Type a name for the schedule.
. Choose a frequency, for example [guimenu]``Weekly`` or [guimenu]``Daily``.
. Click btn:[Create Schedule].

For more information about recurring actions, see xref:administration:actions.adoc#recurring_actions[Recurring Actions].

[NOTE]
====
Repeat this procedure for every organization that contains clients that are not always online.
