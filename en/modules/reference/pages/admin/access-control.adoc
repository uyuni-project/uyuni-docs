= Access Group Management
:description: Manage access groups on this page to view existing groups and create, edit, or delete them as needed to control user permissions and system access
:revdate: 2026-10-07
:page-revdate: {revdate}

The Access Group Management page provides an overview of all existing access groups in your organization and allows administrators to create, edit, or delete them.

Navigate to menu:Admin[Access Control] to open the page.


== Access groups overview

The access groups table lists all custom access groups configured for the current organization.
Predefined roles (such as `{productname} Administrator` or `Organization Administrator`) are built-in system roles and cannot be edited or deleted here; they are managed under menu:Users[User List] and menu:Admin[Users].

Use the `Filter by name or description` field above the table to search for specific access groups.

The table displays the following columns:

* *Name*: The unique name of the access group.
* *Description*: The description of the role and its responsibilities.
* *Organization*: The organization to which the access group belongs.
* *Users*: The number of users currently assigned to the access group.
* *Permissions*: The number of permissions granted to the access group.
* *Actions*: Contains the following actions:
** Edit icon: Click to view and modify group details, permissions, and assigned users.
** Delete icon: Click to delete the access group.

== Namespaces and permissions

Permissions in {productname} are organized hierarchically by namespaces.
Namespaces represent two distinct scopes:

API namespaces::
Represent programmatic API endpoints and XML-RPC/JSON-RPC functions (such as `api.system.bootstrap` or `api.saltkey.accept`).
In the {webui}, API namespaces are indicated by an API icon.
These permissions govern automated calls, scripts, and API interactions with the {productname} Server.

Web UI namespaces::
Represent functional areas, pages, and actions in the {webui}.
For example, the `account.address` namespace corresponds to the menu:User Account[Addresses] page in the {webui}, while `system.details.packages` corresponds to the packages subtab in the system details view.

Each namespace supports two access levels:

* *View*: Grants read-only access to view pages, inspect configurations, or retrieve data.
* *Modify*: Grants full access to create, update, execute, or delete resources within that namespace.

The permissions table includes the following controls:

* *Search*: Filter namespaces by name using the `Filter by name` field.
* *API filter*: Display only permissions for API endpoints.
* *Web filter*: Display only permissions for the {webui}.
* *Only selected filter*: Display only the permissions currently selected for this access group, providing a quick summary of the granted rights.
* *Expand / Collapse*: Toggle individual tree branches or use btn:[Expand All] / btn:[Collapse All] to expand or collapse the entire namespace tree.

[NOTE]
====
{productname} provides descriptions for common namespaces in the permissions table.
SUSE plans to add full descriptions of all namespaces in future releases.
For more information about RBAC architecture and namespace examples, see xref:administration:role-based-access-control.adoc[].

== Edit or delete an access group

To modify an existing access group, use the following procedure:

.Procedure: Editing an access group
[role=procedure]
_____
. In the {webui}, navigate to menu:Admin[Access Control].
. In the `Actions` column of the access group, click the Edit icon.
. The `Access Group Details` page opens with the `Details`, `Namespaces & Permissions`, and `Users` tabs.
. Adjust group properties, permissions, or user assignments as needed across the tabs.
  Note that the organization cannot be changed after creation.
. Click btn:[Update Access Group] at the bottom of the page to save your changes.
_____

To delete an access group, use the following procedure:

.Procedure: Deleting an access group
[role=procedure]
_____
. In the {webui}, navigate to menu:Admin[Access Control].
. In the `Actions` column of the access group, click the Delete icon.
. In the `Delete Access Group` dialog, confirm the deletion.
  Deleting an access group revokes the custom role and its permissions from all assigned users.
_____
